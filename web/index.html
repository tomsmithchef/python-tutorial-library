Introduction to Python Programming Language

This chapter is written for someone who may have never programmed before. The goal is not only to memorize syntax, but to understand what Python is asking you to think about: values, names, instructions, structure, and small repeatable habits that make code easier to read.

1. Python and Programs

Source pages 3-5

Python is a general-purpose programming language. General-purpose means the language is not designed for only one narrow job. The same language can be used to automate boring tasks, analyze data, build a web application, work with files, create a small desktop tool, experiment with artificial intelligence, or write scripts that help manage a computer system. For a beginner, this flexibility matters because the early ideas you learn are not throwaway ideas. Variables, strings, lists, dictionaries, input, output, and operators appear almost everywhere Python is used.

Python is often described as readable. That does not mean every Python program is automatically easy, but it does mean the language tries to keep common actions close to plain English. A line such as print("Hello") is understandable even before you know every technical term around it. The word print names the action, the parentheses hold the information being sent into the action, and the quoted text is the message being displayed.

Beginner mental model

A Python program is a recipe for the computer. Each line gives an instruction. Python reads many simple scripts from top to bottom, carrying values forward as it goes. If a value is placed into a variable, later lines can use that variable instead of typing the value again.

Python is high level, dynamically typed, and usually platform independent for beginner scripts. High level means Python hides many machine-level details so you can focus on the problem you are trying to solve. Dynamically typed means a variable does not need a declared type before you assign a value to it. If you write name = "Amina", Python understands that the value is text because the value itself is text. Platform independent means the same basic script can usually run on Windows, macOS, or Linux as long as Python is installed.

2. Tools, Scripts, and Your First Output

Source pages 6-7

Beginners often confuse Python the language with the program used to write Python. Python is the language and runtime. IDLE, the command-line shell, and PyCharm are tools that help you write or run Python code. An IDE, short for Integrated Development Environment, combines a code editor, project view, run button, terminal, and error display into one workspace. PyCharm is one IDE. You could also write Python in many other editors, but a course may choose one tool so everyone sees similar screens.

A Python file usually ends with .py. If you save a file as hello_world.py, you are telling yourself and your tools that the file contains Python code. The classic first program is short because it teaches several ideas at once: calling a function, passing a string into that function, and viewing output in the console.

hello_world.py
print("Hello, world!")

Try it in your IDE: create a file named hello_world.py, paste the example, and run it from PyCharm.

Expected output 
Hello, world!

The quotes are important because they tell Python that Hello, world! is literal text. The parentheses are also important because they complete the function call. If one quote or parenthesis is missing, Python will not guess what you meant. It will stop and show an error message. At the beginning, many errors are punctuation errors, not deep logic problems.

3. Coding Standards, PEP 8, Comments, and Docstrings

Source pages 8-9 and 16-20

Code is written once but read many times. You may read your own code again tomorrow, your instructor may read it while grading, and a future teammate may read it while fixing a bug. Coding standards exist so code looks predictable. In Python, the best-known style guide is PEP 8, which gives recommendations for names, whitespace, line length, comments, and other habits.

PEP 8 means Python Enhancement Proposal 8. A Python Enhancement Proposal is a written design document used by the Python community. PEP 8 is not a separate programming language and it is not required for Python to run your code. Instead, it is the common style agreement Python programmers use so code from different people still feels familiar. When a class, workplace, or team says “write Python style,” they usually mean “follow PEP 8 unless the project has a specific reason to do something else.”

PEP 8 style habits

Topic Beginner rule Why it matters
One statement per line Avoid squeezing several actions onto one line. It makes code easier to scan and easier to debug.
Spaces around operators Prefer total = price * quantity. The calculation is visually separated from the assignment.
No extra space before calls Write print("Hi"), not print ("Hi"). The function name and call parentheses belong together.
No extra space inside brackets Write cars[1], not cars[ 1 ]. Indexing stays compact and readable.
Block comments Start each line with # and align it with the code it describes. The reader can tell which code the explanation belongs to.
Inline comments Place at least two spaces before #, then one space after it. The code and comment stay visually distinct.

Whitespace matters in two ways. First, whitespace makes code comfortable to read. A line like total = price * quantity is easier to scan than total=price*quantity. Second, indentation has meaning in Python. In many languages, braces mark a block of code. In Python, indentation marks the block. When you later write an if statement or a loop, the indented lines belong to that structure.

Readable style
# Calculate the total price before tax.
quantity = 3
price = 19.99
total = quantity * price

print(total)

Try it in your IDE: run the example once, then change quantity and predict the new output before running again.

Comments begin with #. A good comment explains purpose, context, or a decision that is not obvious from the code itself. Comments should not simply translate every line into English. If a variable is named clearly, the code already says a lot. For example, quantity = 3 rarely needs a comment saying “set quantity to 3.” A better comment explains why that quantity matters.

A docstring is a documentation string. It uses triple quotes and usually appears at the top of a module, function, class, or method. In Lesson 1, you only need to recognize the idea. Later, when you write your own functions, docstrings become a clean way to explain what a function does before someone reads its internal code.

Lesson 1 also distinguishes one-line and multi-line docstrings. A one-line docstring opens and closes on the same line and briefly states the action, such as """Return the account balance.""". A multi-line docstring closes on its own line and gives more context. For scripts, a docstring can describe the script’s purpose and how to run it. For modules, it can summarize the functions, classes, or values the module provides.

Module docstring
"""Practice script for assigning the same value to two variables."""

first_greeting = second_greeting = "Good day"

# Display both assigned variables.
print(first_greeting)
print(second_greeting)

4. Keywords, Statements, Indentation, and Program Structure

Source pages 10-14

Keywords are reserved words that Python uses for its own grammar. Words such as if, while, for, class, return, True, False, and None have special meaning. Because Python needs those words to understand your program, you cannot use them as ordinary variable names. You can explore the full list by running help("keywords") in Python.

Python is case sensitive. That means True and true are not the same thing. The capitalized True is a Boolean literal built into the language. The lowercase true is just a name Python does not know unless you define it yourself. The same rule applies to variable names: first_name, First_Name, and firstName are three different names.

A statement is an instruction Python can execute. Assignment is one kind of statement: score = 10. A print call is another kind: print(score). Some statements create blocks. A block is a group of lines that belong together. In the example below, the indented print line belongs to the if statement.

Indented block
is_ready = True

if is_ready:
    print("The block ran.")

print("The program is done.")

Try it in your IDE: remove the indentation before the first print() and notice how the meaning changes.

When a statement becomes long, Python allows continuation across lines. Parentheses, brackets, and braces are the clearest way to continue a line because Python can see that the expression has not finished yet. A backslash can also continue a line, but beginners should prefer parentheses when possible because they are easier to read and harder to break accidentally.

5. Variables, Constants, Naming, and Types

Source pages 15, 22-23, and 35-36

A variable is a name that refers to a value. Many beginner explanations describe a variable as a box, and that image is helpful at first. A slightly more accurate Python image is a label attached to an object. When you write first_name = "John", Python creates or uses the string object "John" and lets the name first_name refer to it.

Python does not require you to declare the variable type before assigning a value. You do not write string first_name. You simply write the assignment, and Python understands the type from the value. A value in quotes is a string. A whole number such as 5 is an integer. A number with a decimal point such as 5.0 is a float.

Variables and type()
first_name = "John"
age = 25
price = 150.75

print(first_name)
print(type(first_name))
print(type(age))
print(type(price))

Try it in your IDE: add one more variable of your own and print its type.

Good names make code easier to understand. A variable named x is legal, but it tells the reader almost nothing. A variable named total_price explains its role. If a name has multiple words, Python style usually uses lowercase words separated by underscores. Names should not start with a digit, should not contain special characters such as ! or @, and should not be a keyword.

Constants are values that are meant to stay the same while the program runs. Python does not prevent you from changing them, so programmers use uppercase names as a promise: DISCOUNT_RATE = 0.20. The uppercase name tells the reader that the value is part of the program’s setup and should be treated carefully.

Multiple assignment lets you assign several values in one statement. Same-value assignment lets several names point to the same value. These tools are convenient, but clarity still matters. Use them when they make the relationship obvious.

Multiple assignment
first_name, last_name = "John", "Bello"
city = campus = "Ottawa"

print(first_name, last_name)
print(city, campus)

6. Literals, Strings, Escape Sequences, and Formatting

Source pages 24-33 and 51

A literal is a value written directly into the program. In score = 10, the number 10 is a numeric literal. In message = "Welcome", the quoted text is a string literal. Python includes numeric literals, Boolean literals, string literals, the special literal None, and collection literals such as lists, tuples, dictionaries, and sets.

Numeric literals can be integers, floats, or complex numbers. Integers are whole numbers. Floats hold decimal values. Complex numbers use j for the imaginary part. Python can also write integers using binary, octal, or hexadecimal notation, although beginners usually start with ordinary decimal numbers.

Numeric literals
binary_value = 0b1010
decimal_value = 200
float_value = 3.5e2
complex_value = 3.14j

print(binary_value)
print(decimal_value)
print(float_value)
print(complex_value.imag)

Strings are sequences of characters. They can be written with single quotes, double quotes, or triple quotes. Triple quotes are useful for text that spans more than one line. Escape sequences start with a backslash. For example, \n means newline and \t means tab. Escape characters are also used when you need to place a quote inside a string that uses the same quote style.

Strings and methods
sentence = "What a wonderful day"

print(sentence.capitalize())
print(sentence.find("day"))
print(sentence.replace("day", "evening"))
print(sentence.count("a"))

Try it in your IDE: change the sentence and check whether the index returned by find() changes.

String methods return useful transformed values. They do not change the original string because strings are immutable. If you want to keep a transformed value, assign it to a variable. Formatting is another important string skill. The format() method can insert values into a sentence, add commas to large numbers, and display currency-like values with two decimal places.

String method reference

You do not need to memorize every string method at once, but you should know what kind of job each one performs. Methods are called with dot notation, such as sentence.upper().

7. Lists, Tuples, Dictionaries, and Sets

Source pages 34 and 37-55

Collections let one variable hold multiple values. The four collection types introduced in Lesson 1 are lists, tuples, dictionaries, and sets. They are not interchangeable. Each one answers a different beginner question: Do I need order? Do I need to change the collection? Do I need labels? Do I need uniqueness?

Indexing, slicing, and mutability by data type

This is one of the biggest Lesson 1 ideas to keep straight. Some data types are sequences and support numeric indexes. Some are collections but do not use numeric positions. Some can be changed after they are created, and some cannot.

Type Ordered? Indexing / slicing? Changeable? Beginner note
str Yes Yes: school[4], school[1:6] No Strings are sequences of characters, but you cannot replace one character in place.
list Yes Yes: cars[0], cars[2:] Yes Lists are the flexible beginner collection for ordered data.
tuple Yes Yes: fruit_tuple[-1], fruit_tuple[2:6] No Tuples protect ordered data from accidental item replacement.
dict Insertion ordered in modern Python Key lookup, not numeric indexing: car["brand"] Yes Dictionaries use meaningful keys instead of positions.
set No No indexing or slicing Can add/remove items Sets are for unique membership and group comparison, not position.
int, float, bool, None No No No item-level changes These are single values, not containers of values.

Lists

A list is an ordered and changeable collection. Ordered means every item has a position. Changeable means you can add, remove, or replace items after the list is created. Python indexes begin at zero, so the first item is at index 0, the second item is at index 1, and so on. Negative indexes count from the end, making cars[-1] a useful way to refer to the last item.

List operations
cars = ["Honda", "Toyota", "Mercedes", "Ferrari", "Nissan", "Hyundai"]

print(cars[2])
cars[-1] = "Kia"
cars.insert(2, "Chevrolet")
cars.reverse()
print(cars)

Try it in your IDE: print the list after every list method so you can see each change happen.

Lists can be looped through directly when you need each item, or by index when the position matters. A direct loop is easier to read. An index loop is useful when the assignment specifically asks you to use indexes or when you need both the position and the value.

Tuples

A tuple is ordered like a list, but immutable. Once created, its individual items cannot be changed. This makes tuples useful when the data should be protected from accidental edits. Tuples can be indexed, sliced, unpacked into variables, joined with another tuple, counted, and searched with index().

Negative tuple indexing starts from the end, so fruit_tuple[-1] means the last item and fruit_tuple[-2] means the second-last item. Tuple ranges work like list ranges: tuple_name[2:6] includes index 2 and stops before index 6. If a tuple truly needs to be changed, the usual workaround is to convert it to a list, change the list, and convert it back to a tuple.

Dictionaries

A dictionary stores key-value pairs. Instead of remembering that a value is at position 0 or 1, you give it a label. A car dictionary might use the keys "brand", "model", and "year". The values could be "Ford", "Mustang", and 2022. Dictionaries are excellent for representing real-world objects with named properties.

Dictionary operations
car = {

    "model": "Mustang",
    "year": 2022,

print(car["brand"])
print(car.keys())
print(car.items())

Sets

A set is an unordered collection of unique items. If the same value is added more than once, the set keeps only one copy. Sets are especially useful for comparing groups. You can find what two groups have in common with intersection, combine groups with union, find what one group has that another does not with difference, and find values that belong to one group but not both with symmetric difference.

Set operations

print(basketball.union(baseball))
print(baseball.difference(basketball))

8. Type Conversion, Input, Output, and Imports

Source pages 56-60

Type conversion means changing a value from one type to another. Python sometimes performs safe conversions automatically. For example, adding an integer and a float produces a float because the decimal part must be preserved. This is implicit conversion. Explicit conversion happens when you call a function such as int(), float(), str(), list(), tuple(), or set() yourself.

Conversion is powerful but should be done thoughtfully. Converting the string "456" to an integer gives the number 456, which can be used in arithmetic. Converting -10.6 to an integer gives -10, which loses the decimal portion. That is why the lesson notes warn that type casting can lose data.

Conversion
num_int = 123
num_float = 1.23
print(num_int + num_float)

num_text = "456"
num_value = int(num_text)
print(num_int + num_value)

User input is collected with input(). The important beginner rule is that input() always returns a string. If the user types 7, Python receives "7", not the integer 7. To add numbers entered by a user, convert the input first.

Input pattern
first_number = int(input("Enter the first number: "))
second_number = int(input("Enter the second number: "))
total = first_number + second_number

print("The sum of {0} and {1} is {2}".format(first_number, second_number, total))

Imports let a program use code from another module. A module is a Python file containing definitions and statements. Python includes many useful standard modules. The math module contains mathematical constants and functions, including pi. You can import the module as a whole with import math, or import a specific name with from math import pi.

9. Operators

Source pages 61-66

Operators perform actions with values. Arithmetic operators handle math. Comparison operators ask questions and return True or False. Assignment operators update variables. Logical operators combine conditions. Identity and membership operators answer more specialized questions.

Arithmetic operators include addition, subtraction, multiplication, division, modulus, floor division, and exponentiation. Division with / returns a float. Floor division with // returns the whole-number floor of the result. Modulus with % returns the remainder, which is useful for patterns such as checking whether a number is even.

Arithmetic and comparison
x = 15
y = 4

print("x + y =", x + y)
print("x - y =", x - y)
print("x * y =", x * y)
print("x > y is", x > y)
print("x < y is", x < y)

The assignment operator = stores a value in a variable. The comparison operator == checks whether two values are equal. This difference is one of the most important beginner details in programming. Writing total = 12 assigns the value. Writing total == 12 asks a question whose answer is True or False.

Logical operators are and, or, and not. The operator and requires both sides to be true. The operator or requires at least one side to be true. The operator not reverses a Boolean value. Membership operators such as in and not in check whether a value appears in a collection or string.

1. Flow Control

Source page 3

Flow control is the part of programming that decides which instructions run, which instructions are skipped, and which instructions repeat. Without flow control, a program runs straight from top to bottom every time. That is useful for very small scripts, but real programs usually need to respond to changing information. A loan program might approve one customer and reject another. A grade program might print a different message for an A, B, C, or failing mark. A game might decide that Player 1 wins, Player 2 wins, or the round is a draw.

A decision-making statement evaluates a condition. A condition is an expression that becomes either True or False. If the condition is true, Python runs the block connected to that condition. If the condition is false, Python skips that block and may run a different block instead. Conditions usually use comparison operators such as >, <, ==, >=, and <=, often combined with logical operators such as and and or.

Decision statement reference

Statement Purpose Beginner use case
if Run a block only when one condition is true. Print a message only if a number is positive.
if...else Choose between two possible paths. Approve or reject a loan when there are two outcomes.
if...elif...else Check several possible conditions in order. Classify a number as positive, zero, or negative.
Nested if Place one decision inside another decision. Check a second requirement only after the first requirement passes.

Beginner mental model

Think of flow control as a fork in the road. The program reaches a question, checks the answer, and follows the matching path. Indentation shows exactly which lines belong to each path.

2. If, Else, and Elif

Source pages 4-6 and 8

The simplest decision uses if. An if statement has a condition followed by a colon. The indented block underneath runs only when the condition is true. If the condition is false, Python skips the indented block and continues after it.

Simple if statement
num = 30

if num > 0:
    print(num, "is a positive number.")

print("Outside the if statement.")

Try it in your IDE: change num to a negative value and observe which line no longer runs.

An if...else statement gives Python two paths. If the condition is true, the if block runs. If the condition is false, the else block runs. This is useful when exactly one of two outcomes should happen.

If and else
num = 10

if num >= 0:
    print("Positive or zero")
else:
    print("Negative number")

Condition operators

Conditions are built from comparisons and logical combinations. These expressions do not print by themselves; they evaluate to True or False, and the decision statement uses that result.

Operator Meaning Example
==Equal tochoice == "Rock"
!=Not equal tochoice != "Paper"
>Greater thanincome > 30000
<Less thanscore < 600
>=Greater than or equal toyears >= 2

When there are more than two possible outcomes, use elif, short for "else if." Python checks the first condition, then each elif condition in order, and finally the optional else block if nothing else matched. The order matters. Put the most specific checks where they make the most sense, and make sure the final else represents the leftover case.

If, elif, and else
num = 5.87

    print("Positive number")
elif num == 0:
    print("Zero")
else:
    print("Negative number")

3. Nested Decisions

Source page 7

A nested if statement is an if statement placed inside another if statement. Nesting is sometimes useful because one question only matters after another question has already been answered. For example, a number can only be checked for being exactly zero after the program has already decided it is not negative.

Nested if statement
num = float(input("Enter a number: "))

if num >= 0:
    if num == 0:
        print("Zero")
    else:
        print("Positive number")
else:
    print("Negative number")

The risk with nesting is readability. Every indentation level asks the reader to keep more context in their head. Nested decisions are not wrong, but beginners should use them carefully. If a nested block becomes hard to explain out loud, the program may be easier to understand with elif, helper variables, or smaller functions in later lessons.

4. Loops

Source pages 9-11

A loop repeats a statement or a group of statements. Loops are one of the main reasons programming is powerful: the computer can repeat a task hundreds or thousands of times without getting tired. Lesson 2 introduces while loops, for loops, and nested loops.

A while loop repeats while a condition remains true. Because the condition is checked before each repetition, the loop may run many times, one time, or not at all. A common beginner pattern is to create a counter before the loop, check the counter in the condition, and update the counter inside the loop. Forgetting the update is a classic way to create an infinite loop.

While loop counter
i = 1

while i <= 5:
    print(i)
    i = i + 1

A for loop is used to iterate over a sequence or iterable object. A sequence can be a list, tuple, string, or a range of numbers. The range() function is common when you need a series of integers. range(1, 6) produces the values 1 through 5, because the ending value is not included.

For loop with range
for i in range(1, 6):
    print(i)

A nested loop is a loop inside another loop. Nested loops are useful for tables, grids, and combinations, but they multiply the amount of work. If an outer loop runs 10 times and an inner loop runs 10 times, the inner body can run 100 times. That is powerful, but it should be intentional.

Loop reference

Loop type Syntax pattern Best beginner use
while while condition: Repeat while something remains true, such as "keep asking until valid".
for for value in sequence: Visit every item in a list, tuple, string, range, or other iterable.
Nested loop A loop inside another loop. Build tables, grids, or compare combinations of items.

Understanding range()

range() creates a sequence of integers for looping. The stop value is not included, which is why range(1, 6) gives 1 through 5.

Pattern Values produced
range(6)0, 1, 2, 3, 4, 5
range(1, 6)1, 2, 3, 4, 5
range(2, 11, 2)2, 4, 6, 8, 10

Accumulator and filter patterns

Several Lesson 2 practice questions ask you to build a result gradually. When you add numbers one at a time, use an accumulator. When you sort values into different groups, use one or more result lists. These are not new Python features; they are reliable loop patterns.

Accumulator and filter loop
numbers = [6, 5, 3, 8, 4, 2, 5, 4, 11]

5. Break and Continue

Source pages 14-16

Sometimes a loop should not run all the way to its natural end. The break statement exits the loop immediately. After break, Python continues with the first line after the loop. This is useful when the program has found what it was looking for or when continuing would be unnecessary.

Break
for val in "Hello":
    if val == "e":
        break
    print(val)

print("The end")

The continue statement skips the rest of the current iteration and moves to the next one. It does not end the whole loop. In the example below, the letter e is skipped, but the loop continues with the remaining letters.

Continue
for val in "Hello":
    if val == "e":
        continue
    print(val)

print("The end")

break vs continue

Statement Effect In "Hello" example
break Exit the whole loop immediately. The loop stops when it reaches "e".
continue Skip the rest of the current iteration and continue with the next item. The letter "e" is skipped, but later letters still run.

6. Command-Line Arguments

Source pages 12-13 and 17

Command-line arguments are values typed after the script name when a program is run from a terminal. They let a script receive information without using input(). This matters when you want to run a program from PowerShell, Command Prompt, a scheduled task, another program, or an automated workflow.

For example, a script named add_numbers.py might be run as python add_numbers.py 4 4 4. The script name is the command being executed, and the values after it are arguments. Lesson 2 introduces three ways to work with those arguments: sys.argv, getopt, and argparse.

Command-line argument approaches

Tool What it gives you When to use it

getopt Parsing for short and long command-line options. Scripts that need option flags like -h or -o Colors.
argparse A structured parser with help messages, positional arguments, optional arguments, defaults, and validation support. Most new command-line programs.

Input vs command-line arguments

input() asks the user questions while the program is running. Command-line arguments are provided before the program starts. Both approaches collect information, but they fit different styles of program use.

7. sys.argv

Source pages 18-19

The sys module gives access to parts of the Python runtime environment. One important value in this module is sys.argv, a list containing the command-line arguments. The first item, sys.argv[0], is the script name. The remaining items are the values typed after the script name. Because sys.argv is a list, len(sys.argv) tells you how many items it contains.

8. getopt

Source pages 20-21

The getopt module helps parse command-line options. Options are arguments that usually begin with a dash, such as -h for help or -o Colors for an option named o with a value. Compared with plain sys.argv, getopt gives more structure, but it also requires more setup.

getopt pattern
import getopt
import sys

argv = sys.argv[1:]

try:
    opts, args = getopt.getopt(argv, "ho:v")
    print(opts)
    print(args)
except getopt.GetoptError:
    print("Something went wrong!")
    sys.exit(2)

In the option string "ho:v", the letters describe which short options are accepted. A colon after a letter means that option expects a value. This style is common in older command-line tools, but for many new Python programs, argparse is friendlier.

getopt.getopt() parameters

Parameter Meaning
argsThe list of command-line arguments to parse, usually sys.argv[1:].
optionsA string of short option letters the script recognizes. A colon after a letter means the option requires a value.
long_optionsA list of long option names. An equals sign after a name means the long option requires a value.
Return valueA pair: parsed option/value pairs and leftover arguments after options are removed.
GetoptErrorThe exception raised when parsing fails.

9. argparse

Source pages 22-25

The argparse module is the preferred standard-library tool for many command-line programs. It can define positional arguments, optional arguments, help messages, descriptions, defaults, and type conversions. A positional argument is required because its position matters. An optional argument usually begins with a dash and can be omitted.

argparse pattern
import argparse

parser = argparse.ArgumentParser(description="Add two numbers.")
parser.add_argument("first_number", help="Enter the first number")
parser.add_argument("second_number", help="Enter the second number")
args = parser.parse_args()

first_number = int(args.first_number)
second_number = int(args.second_number)

print("The sum of the two numbers is", first_number + second_number)

A major benefit of argparse is that it can generate help text. If the user runs a script with -h, argparse can explain what arguments the script expects. That makes command-line tools easier to use and easier to grade because the interface is documented by the program itself.

argparse concepts

Concept Description
ArgumentParserThe parser object that describes and reads the command-line interface.
DescriptionText that explains the script when help is requested.
Positional argumentA required argument identified by its position, such as the first and second number.
Optional argumentAn argument usually introduced with a dash, such as -h or --verbose.
parse_args()Reads the command-line values and returns an object containing the parsed arguments.
Type castingCommand-line values start as strings, so number arguments must be converted or configured as numeric types.

Designing larger decision problems

The date challenge at the end of Lesson 2 is larger than the first if examples because it combines validation, month rules, leap-year logic, and rollover from one month or year to the next. The trick is to avoid writing the whole program at once. Break the problem into questions that can each be answered with one decision.

Question Condition idea Why it matters
Is the month valid? 1 <= month <= 12 No day can be valid if the month itself is not valid.
How many days are in this month? 31-day months, 30-day months, and February are separate cases. The maximum valid day depends on the month.

Does the date roll over? If day == days_in_month, reset day to 1 and advance the month. December 31 also advances the year and resets the month to January.

Once you understand functions, your programs become easier to organize, test, explain, and expand.

1. Why Functions Matter

Source page 3

A function is a group of related statements that performs a specific task. That definition sounds simple, but it changes how you design programs. Without functions, a program often becomes one long sequence of instructions. At first that feels direct, but as the program grows, repeated code appears, small changes become harder to make, and it becomes difficult to tell where one idea ends and another begins.

Functions solve that problem by creating smaller modules of behavior. A program that calculates interest can have one function for collecting input, one function for calculating interest, and one main function that controls the order of events. A loan program can use a function to check whether a customer qualifies. A list-processing program can use a function to count only integer values. The function name becomes a readable label for the task.

Beginner mental model

Think of a function as a reusable mini-program inside your program. It does not run just because it exists. It runs when you call it.

What functions are responsible for

Purpose What it means for a beginner
Organization A function gives a name to a task, so the main program can read like a short sequence of meaningful actions.
Reuse If the same calculation or validation is needed more than once, a function lets you write it once and call it many times.
Testing Small functions are easier to test because you can give them inputs and check the returned result.
Maintenance When a rule changes, updating one function is safer than searching for repeated copies of the same logic.

2. Defining and Calling a Function

Source page 4

Python creates functions with the def keyword. The function definition starts with def, then the function name, then parentheses, then a colon. The indented block underneath is the function body. The body contains the statements that run when the function is called.

Function definition and call
def greet(name):
    """Print a friendly greeting for the given name."""
    print("Hello, " + name + ". Good morning!")

greet("Joseph")

Try it in your IDE: change the value passed into greet() and run the file again.

The line def greet(name): defines the function. The line greet("Joseph") calls it. The value "Joseph" is passed into the function, and inside the function that value is available through the parameter named name. If a function expects one argument, it must be called with one argument unless a default value is provided.

A function definition cannot be empty. If you need to create a placeholder function before you know its body, use the pass statement. pass tells Python that the empty block is intentional.

Function anatomy

Piece Example Meaning
Keyword def Tells Python you are defining a function.
Name greet The label you will use later when you call the function.
Parameters (name) Names for values the function expects to receive.
Colon : Starts the indented function body.
Body print(...) The statements that run when the function is called.
Call greet("Joseph") Runs the function and sends argument values into it.

3. Parameters, Arguments, Defaults, and Flexible Inputs

Source pages 6-7

A parameter is the name written in the function definition. An argument is the actual value supplied when the function is called. In def greet(name):, name is a parameter. In greet("Joseph"), "Joseph" is an argument. Beginners often use these words interchangeably, but the distinction helps when reading error messages.

Default parameter values make an argument optional. If the caller does not provide that argument, Python uses the default. Keyword arguments let the caller name the argument being supplied, which can make calls easier to read and lets arguments appear in a different order.

Default and keyword arguments
def student(firstname, lastname="King", colour="red"):
    print(firstname, lastname, "favourite colour is", colour)

student(firstname="James")
student(firstname="James", colour="White")
student(firstname="Ada", lastname="Lovelace", colour="Blue")

Sometimes a function needs to accept an unknown number of arguments. A parameter beginning with *, often written as *args, collects extra positional arguments into a tuple. A parameter beginning with **, often written as **kwargs, collects extra keyword arguments into a dictionary.

Required parameters are still required

Default values only make the parameters with defaults optional. If a function has def student(firstname, lastname="King"):, the caller still has to provide firstname. Calling the function with only lastname="Gates" would raise an error because the required first name was never supplied.

*args and **kwargs
def show_colours(*colours):
    print("Second colour:", colours[1])

def show_named_colours(**colours):
    print("Third colour:", colours["third_colour"])

show_colours("Red", "Yellow", "Blue")
show_named_colours(first_colour="Red", second_colour="Yellow", third_colour="Blue")

Argument types reference

Kind Example Use it when
Positional argument student("Ada", "Lovelace") The order of values clearly matches the parameter order.
Keyword argument student(firstname="Ada") You want the call to be easier to read or you want to skip over a defaulted argument.
Default parameter lastname="King" The function should have a normal value to use when the caller leaves that argument out.
*args def total(*numbers): The function may receive any number of positional values. Python stores them in a tuple.
**kwargs def profile(**details): The function may receive any number of named values. Python stores them in a dictionary.

4. Scope and Lifetime of Variables

Source page 5

Scope describes where a variable is recognized. A variable created inside a function is local to that function. It exists while the function is running and is separate from variables outside the function, even if the names match. This protects functions from accidentally changing unrelated values.

Local and outer variables
def my_func():
    x = 100
    print("Value inside function:", x)

x = 200
my_func()
print("Value outside function:", x)

The two variables named x are not the same variable. The local x belongs to the function call. The outer x belongs to the surrounding program. This idea becomes especially important when you write functions that calculate and return values. Instead of relying on a function to mysteriously change outside data, design it to receive inputs and return a result.

5. Docstrings and Return Values

Source pages 8-9

A docstring documents what a function does. It appears as the first statement inside the function body, usually inside triple quotes. Good docstrings are short, direct, and useful to someone who wants to call the function without reading every internal line.

A function can display information with print(), but printing is not the same as returning. print() sends text to the console. return sends a value back to the place where the function was called. Returned values can be stored in variables, used in calculations, passed to other functions, or printed later.

Returning a value
def add_numbers(x, y):
    """Return the sum of two values."""
    total = x + y
    return total

num1 = 5
num2 = 6
answer = add_numbers(num1, num2)
print("The sum is", answer)

Try it in your IDE: call the function with two different numbers and store the returned result in a new variable.

Docstring and return reference

Feature How to read it Beginner note
Docstring """Return the sum of two values.""" It documents the function for people and for Python's help tools.
Accessing docs print(add_numbers.__doc__) __doc__ is a special attribute that stores the docstring.
Return value return total Stops the function and sends a value back to the caller.
No return A function reaches the end without return. Python gives back None, which means “no useful value was returned.”

7. Recursion

Source pages 19-25

Recursion happens when a function calls itself directly or indirectly. It can be useful when a problem can be described in terms of a smaller version of the same problem. For example, counting down from 5 can be described as printing 5 and then counting down from 4. Factorial can be described as multiplying a number by the factorial of the number before it.

Every recursive function needs a base case. The base case is the condition that stops the recursion. If a recursive function never reaches a base case, it keeps calling itself until Python raises a RecursionError. Python has a recursion limit to prevent a program from consuming memory forever.

Countdown recursion
def countdown(num):
    print(num)
    if num == 0:
        return
    countdown(num - 1)

countdown(5)

Factorial is another classic recursion example. The factorial of 4 means 4 * 3 * 2 * 1. A recursive version says: the factorial of n is n times the factorial of n - 1, until the base case is reached. Python's math module also provides math.factorial(), so the recursive version is mainly used here to understand the pattern.

Recursive factorial pattern
def recursive_factorial(n):
    if n == 1:
        return 1
    return n * recursive_factorial(n - 1)

print(recursive_factorial(4))

Recursion can make some problems elegant, but it is not always the best beginner tool. Recursive calls use memory, can be harder to debug, and require careful reasoning. If a loop is simpler and easier to read, a loop may be the better choice.

Recursion reference

Concept Meaning Why it matters
Base case The condition that stops the function from calling itself again. Without it, the function eventually raises RecursionError.
Recursive case The part of the function that calls itself with a smaller or simpler input. Each call should move closer to the base case.
Separate calls Each recursive call has its own local variables. Variables from one call do not automatically overwrite another call's local variables.
Recursion limit sys.getrecursionlimit() reports the limit; sys.setrecursionlimit(n) changes it. Changing the limit is rarely needed for beginner programs; a missing base case is usually the real bug.
Factorial shortcut math.factorial(n) Python's standard library already provides a tested factorial function.

8. Anonymous Lambda Functions

Source pages 26-29

A lambda function is a small anonymous function created with the lambda keyword. Anonymous means the function does not need a regular name created with def. Lambda functions are useful when you need a short function for a short period of time, especially with tools like filter() and map().

A lambda can have any number of arguments, but only one expression. The expression is evaluated and returned automatically. If the logic needs several statements, a regular def function is clearer.

Lambda basics
def triple_function(x):
    return x * 3

triple_value = lambda x: x * 3

print(triple_function(5))
print(triple_value(5))
Lambda with if-else
min_value = lambda a, b: a if a < b else b
print(min_value(1, 2))

Lambda reference

Rule Example Beginner interpretation
Basic syntax lambda x: x * 3 Take x, evaluate x * 3, and return the result automatically.
Multiple inputs lambda x, y: x * y A lambda can accept more than one argument.
One expression lambda a, b: a if a < b else b Conditional expressions are allowed, but full multi-line logic belongs in def.
Best use filter(lambda n: n % 2 == 0, numbers) Use lambdas for short functions passed into another function.

9. filter(), map(), and Lambda

Source pages 30-34

The filter() function keeps items from an iterable when a function returns True for those items. The map() function transforms each item in an iterable by applying a function to it. Both return iterator objects, so beginners often wrap them in list() to view the result.

The difference is important. Filtering chooses which items stay. Mapping changes each item into a new value. If you are selecting only even numbers, think filter(). If you are doubling every number, think map().

filter and map
list_one = [1, 7, 100, 8, 9, 17, 25, 16, 35, 80, 5, 4]

is_even_flags = list(map(lambda x: x % 2 == 0, list_one))
even_numbers = list(filter(lambda x: x % 2 == 0, list_one))
doubled_numbers = list(map(lambda x: x * 2, list_one))

print(is_even_flags)
print(even_numbers)
print(doubled_numbers)

You can also combine filter() with membership tests. To find the intersection of two lists, filter the second list by keeping only values that also appear in the first list. Later lessons may show other ways to solve this, but this example reinforces how functions can be passed into functions.

filter(), map(), and membership reference

Tool Pattern Result idea
filter() list(filter(lambda x: x % 2 == 0, numbers)) Keep only the values where the function returns True.
map() list(map(lambda x: x * 2, numbers)) Build a new value for every item in the original iterable.
Boolean map list(map(lambda x: x % 2 == 0, numbers)) Return True or False for each original item.
Intersection list(filter(lambda x: x in first_list, second_list)) Keep items from the second list only when they also appear in the first list.

1. Files and the File Workflow

Source page 3

A file is a named location on disk used to store related information. Variables and lists are useful while a program is running, but they normally disappear when the program exits. Files solve that problem by saving data in non-volatile storage, such as a hard drive or solid-state drive. A coffee inventory program, for example, needs its records to still exist tomorrow. A file gives the program a place to keep them.

File input/output, often shortened to file I/O, follows a simple pattern: open the file, perform an operation, and close the file. The operation might be reading existing data, writing new data, appending more data to the end, or copying content into another file. Closing is important because it releases the operating-system resources connected to that file and helps ensure pending writes are completed.

Beginner mental model

Opening a file is like checking out a notebook from storage. Reading or writing is the work you do with the notebook. Closing returns it safely so the system knows you are finished.

2. Opening and Closing Files

Source pages 4-5

Python opens files with the built-in open() function. The function returns a file object, sometimes called a handle, that lets the program read from or write to the file. The file mode tells Python what kind of access you want. Mode r reads, w writes and truncates existing content, a appends to the end, x creates a new file only if it does not already exist, b means binary mode, and + allows updating.

File mode reference

Mode Name What it does
r Read Opens an existing file for reading. This is the default mode. It raises an error if the file does not exist.
w Write Creates a file if needed and erases existing content. Use carefully because old data is replaced.
x Exclusive creation Creates a new file and raises an error if a file with that name already exists.
a Append Creates a file if needed and writes new content at the end without erasing existing content.
t Text Reads and writes strings. This is the default companion mode for normal text files.
b Binary Reads and writes bytes, which is used for non-text data such as images or compiled files.
+ Update Adds both reading and writing ability, such as r+ or w+.
Opening files
read_file = open("cars.txt", "r", encoding="utf-8")
write_file = open("notes.txt", "w", encoding="utf-8")
append_file = open("inventory.txt", "a", encoding="utf-8")

read_file.close()
write_file.close()
append_file.close()

The safer modern pattern is the with statement. A with block automatically closes the file when the block ends, even if an error occurs inside the block. For beginner file work, prefer with open(...) unless an assignment specifically asks for manual closing.

3. Writing and Reading Data

Source pages 6 and 11-13

To write to a file, open it in write, append, or exclusive-creation mode. Write mode w creates the file if needed but erases existing content if the file already exists. Append mode a keeps existing content and adds new content to the end. That difference matters in inventory-style assignments, where new records should not erase old records.

Writing lines
with open("myfile.txt", "w", encoding="utf-8") as my_file:
    my_file.write("Willis College Header\n")
    my_file.write("Willis College body 1\n")
    my_file.write("Willis College body 2\n")

Reading can happen in several ways. read() returns the file content as a string. If you pass a size, it reads up to that many characters. readline() reads one line. readlines() returns a list of lines. A for loop can also read a file line by line, which is often the cleanest pattern for large files.

Reading line by line
cars = []

with open("cars.txt", "r", encoding="utf-8") as file:
    for line in file:
        cars.append(line.strip())

print(cars)

5. Modules

Source pages 14-19

A module is a Python file that contains related code. If you create a file named calculator.py, then calculator is the module name. A module can contain functions, variables, classes, and other statements. Modules help keep programs organized because related behavior can live in its own file instead of being mixed into one large script.

A calculator module might hold functions such as add(), subtract(), multiply(), and divide(). A separate main.py file can import that module and use its functions. This separates reusable logic from the script that runs the program.

calculator.py
def add(num_one, num_two):
    """Return the sum of two numbers."""
    return num_one + num_two

def subtract(num_one, num_two):
    """Return num_one minus num_two."""
    return num_one - num_two

def multiply(num_one, num_two):
    """Return the product of two numbers."""
    return num_one * num_two

def divide(num_one, num_two):
    """Return num_one divided by num_two."""
    return num_one / num_two
main.py
import calculator as cal

print(cal.add(1, 5))
print(cal.subtract(6, 9))
print(cal.multiply(1, 5))
print(cal.divide(10, 2))

A module can be imported by another file, or it can be run directly as a script. Python sets the special variable __name__ to "__main__" only for the file being run directly. That is why many examples use an if __name__ == "__main__": guard. It lets a file provide reusable functions when imported, while still having a starting point when run as the main program.

Main guard pattern
import calculator as cal

def main():
    print(cal.add(1, 5))
    print(cal.divide(10, 2))

if __name__ == "__main__":
    main()

PEP 8 recommends short lowercase module names. Imports should appear near the top of the file, after any module comment or docstring. Put imports on separate lines and group standard-library imports, third-party imports, and application-specific imports with blank lines between groups.

Module coding standard reference

Place imports near the top Readers can immediately see what outside code the file depends on.
Use separate import lines import os and import sys on separate lines are easier to scan and edit.

6. Import Styles and Module Namespaces

Source pages 20-21

The simplest import style is import calculator. With that style, you access a function using the module name and dot operator, such as calculator.add(1, 2). You can also give the module an alias with import calculator as cal, then call cal.add(1, 2).

Python can import specific objects into the current namespace with from calculator import add. After that import, you can call add(1, 2) without writing the module name. Python also allows from calculator import *, but importing everything is usually discouraged because it becomes harder to see where names came from and easier to accidentally overwrite a name.

Import styles
import calculator
import calculator as cal
from calculator import add

print(calculator.add(1, 2))
print(cal.add(1, 2))
print(add(1, 2))

A module is initialized the first time it is imported during a Python session. If the same module is imported again, Python usually reuses the already-loaded module. That makes imports efficient, but it also means changes during an interactive session may require restarting the session or reloading the module.

Import style reference

Import module import calculator Keeps names clear because calls include the module name, such as calculator.add().
Import with alias import calculator as cal Shortens a long module name while preserving the module namespace.
Import one object from calculator import add Useful when one function or constant is used often and the source is still obvious.
Import all from calculator import * Allowed by Python, but avoid it in normal beginner code because it hides where names came from.

1. Data Manipulation and Parsing

Source page 3

Data manipulation means taking raw information and reshaping it into a form that is easier to understand, analyze, or use in another program. A raw dataset might contain thousands of rows, inconsistent dates, empty cells, duplicate records, columns you do not need, and values that are technically present but clearly wrong. Manipulation is the process of organizing that data: selecting useful parts, correcting mistakes, filling or removing missing values, grouping related rows, and producing summaries.

Parsing is closely related. When Python parses data, it reads information from a source and interprets its structure. A CSV file uses commas to separate fields. A JSON file stores nested key-value data. A text file may use spaces or tabs. Pandas helps Python parse these formats into data structures you can inspect and manipulate.

For a beginner, the important mindset shift is that Pandas is not just another way to store values. It is a workflow library. You load data, inspect it, clean it, analyze it, and sometimes export or save the result. Lesson 5 moves through that whole path.

Beginner mental model

Think of a Pandas dataset as a table with labels. The labels help you ask questions like "show me this column," "show me these rows," "summarize this group," or "replace missing values in this field."

3. Pandas Series

Source pages 7-11

A Series is one of the two primary Pandas data structures. It is one-dimensional, which means it behaves like a single labeled column of data. A Series can store many Python-style data types, including integers, floats, strings, and Boolean values. The labels attached to the values are called the index.

If you create a Series from a list and do not provide labels, Pandas creates a default integer index that starts at 0. This should feel familiar from list indexing. 4. Pandas DataFrames

Source pages 12-14

A DataFrame is the second primary Pandas data structure. It is two-dimensional, with labeled rows and labeled columns. If a Series is like one labeled column, a DataFrame is like a complete table. This makes DataFrames feel similar to spreadsheets, but they are controlled by Python code and can handle repeatable data workflows much more reliably than manual clicking.

DataFrames have a row index and column labels. The row index identifies rows. The column labels identify fields such as Name, Age, Salary, or Engine Information.EngineType. Columns can contain different data types, so one column might store strings while another stores integers or floats.

7. Cleaning Empty Cells, Wrong Formats, Wrong Data, and Duplicates

Source pages 21-24

Data cleaning is the process of making a dataset trustworthy enough for analysis. The chapter focuses on four common problems: empty cells, wrong formats, wrong data, and duplicate records. These problems matter because analysis methods do exactly what the data tells them to do. If the dataset contains blanks, impossible values, or repeated records, your summary can be misleading.

Empty cells can be removed with dropna() or replaced with fillna(). By default, many Pandas cleaning methods return a new DataFrame and leave the original unchanged. If you want to change the original object directly, some methods accept inplace=True. Beginners should be deliberate here: assigning the result to a new variable is often clearer because you can compare before and after.

Handle missing values
import pandas as pd

df_cars = pd.read_csv("cars.csv")

cleaned = df_cars.dropna()
df_cars["Dimensions.Length"].fillna(10, inplace=True)

Wrong format means a value exists but is stored in a form that makes analysis difficult. Dates are a common example. A date column may contain strings that should be converted to date-time values. Pandas provides pd.to_datetime() for this. After conversion, rows that still cannot be converted can be removed with dropna(subset=[...]).

Convert date formats
import pandas as pd

df = pd.read_csv("cars.csv")

df["Date"] = pd.to_datetime(df["Date"], errors="coerce")
df.dropna(subset=["Date"], inplace=True)

Wrong data means the value is in the right general format but is not believable or valid. A speed of 1000 km/h in a normal car dataset is probably not a formatting issue; it is a bad value. In a small dataset, you might replace one value with df.loc[row_index, "ColumnName"] = new_value. In a larger dataset, you might loop over indexes and replace or drop rows that fall outside a boundary.

Replace or remove wrong data
import pandas as pd

df = pd.read_csv("cars.csv")

for row_index in df.index:
    if df.loc[row_index, "Speed"] > 150:
        df.loc[row_index, "Speed"] = 150

for row_index in df.index:
    if df.loc[row_index, "Speed"] < 0:
        df.drop(row_index, inplace=True)

Duplicate records can be detected with duplicated(). It returns Boolean values for rows: True for a duplicate and False otherwise. To remove duplicates, use drop_duplicates(). With inplace=True, the original DataFrame is modified.

Find and remove duplicates
import pandas as pd

df = pd.read_csv("cars.csv")

print(df.duplicated())
df.drop_duplicates(inplace=True)

10. Python Pickle: Storing and Loading Objects

Source pages 35-42

Pickle is a Python module for serialization and deserialization. Serialization means converting an object in memory into a byte stream that can be written to disk, sent over a network, or stored for later. Deserialization reverses the process and reconstructs the object from the byte stream.

Pickle can be useful when you want to save program state, cache Python objects, store objects in a database, or send Python data between Python programs. It is Python-specific, so it is not a good choice when another programming language needs to read the data. CSV and JSON are better cross-language formats.

Security warning

Never unpickle data from an untrusted or unauthenticated source. Pickle can execute instructions during loading, so malicious pickle files are dangerous.

Pickle module interface

Tool What it does
pickle.dump(obj, file)Serializes an object and writes it to an open binary file.
pickle.load(file)Reads a pickled object from an open binary file and reconstructs it.
pickle.dumps(obj)Serializes an object and returns bytes instead of writing a file.
pickle.loads(bytes)Reconstructs an object from a bytes object.
pickle.HIGHEST_PROTOCOLThe highest protocol version available in the current Python version.
pickle.DEFAULT_PROTOCOLThe protocol Python uses when you do not choose one.

Protocol and compatibility arguments

The full Pickle functions include optional arguments for protocol and compatibility. In beginner code, you will most often rely on the defaults, but the names are worth recognizing when you see them in documentation.

Argument Where it appears Meaning
protocol dump() and dumps() Chooses the Pickle protocol version. If omitted, Python uses the default protocol. A negative value selects the highest available protocol.
fix_imports dump() and load() Helps map old Python 2 module names to Python 3 names for compatibility with older pickle streams.
encoding and errors load() and loads() Control how Python 2 string data is decoded when older pickle data is loaded in Python 3.

Pickle files are opened in binary mode. Use "wb" when writing a pickle file and "rb" when reading one. The w and r mean write and read; the b means binary.

Write and read a pickle file
import pickle
import numpy as np

my_data_dict = {
    "location_one": np.random.random(20),
    "location_two": np.random.random(20)
}

with open("pickle.pkl", "wb") as pickle_file:
    pickle.dump(my_data_dict, pickle_file)

with open("pickle.pkl", "rb") as pickle_file:
    my_data = pickle.load(pickle_file)

print(my_data)

Picklable object types

Pickle can handle many ordinary Python objects, including Booleans, integers, floats, complex numbers, strings, tuples, lists, sets, and dictionaries that contain picklable objects. Classes and functions can also be pickled when they are defined at the top level of a module.

Pickle is also sensitive to Python context. If a pickle file was created with a different Python version or with custom classes that no longer exist in the same module location, loading may fail. This is another reason to use Pickle for trusted Python-to-Python workflows, not for long-term public data exchange.

Pickle exceptions

Exception Meaning
pickle.PickleErrorBase class for Pickle-related exceptions.
pickle.PicklingErrorRaised when an object cannot be pickled.
pickle.UnpicklingErrorRaised when loading fails because data is corrupted, invalid, or unsafe.

To explore Pickle further in a Python console, import the module and run help(pickle). This follows the same habit from earlier lessons: when a module or keyword is unfamiliar, use Python's built-in help system to inspect it.

1. Errors and Exceptions

Source page 3

An error is a problem that prevents a program from continuing normally. Some errors happen before the program can even run. Others happen while the program is running. Python reports these problems with error messages that include the type of error, the location where Python noticed the problem, and a short explanation.

The first broad category is a syntax error. Syntax is the grammar of the programming language. A missing colon after an if statement, mismatched parentheses, inconsistent indentation, a missing comma, or a keyword in the wrong place can all produce syntax errors. Python cannot understand the structure, so it stops before the program logic begins.

Syntax error example
age = 20

if age >= 18
    print("Adult")

The code above is missing a colon after the condition. Python has not reached a risky runtime situation; it cannot parse the instruction at all. Fixing syntax errors usually means correcting punctuation, indentation, spelling, or structure.

The second broad category is a runtime exception. In the source lesson, these are described as logical errors because the program may be written in valid Python syntax but still fail during execution. Dividing by zero, reading a file that does not exist, converting "abc" to an integer, or accessing a list item outside its index range are runtime problems. Python raises an exception to represent the problem.

Runtime exception example
numbers = [10, 20, 30]

print(numbers[5])
Likely result 
IndexError: list index out of range

The list syntax is valid, and print() is being called correctly. The problem is that the program asks for index 5 when the list only has indexes 0, 1, and 2. If an exception is not handled, Python stops the current operation and reports the error.

Beginner mental model

Syntax errors mean Python cannot understand the sentence. Exceptions mean Python understood the sentence, tried to follow it, and hit a problem while doing the work.

3. Handling Exceptions with try and except

Source pages 6-8

Exception handling starts with a try statement. The try block contains code that might fail. The except block contains code that should run if a matching exception occurs. The risky code goes in try; the recovery or explanation goes in except.

Basic try/except shape
try:
    risky_code()
except SomeException:
    handle_the_problem()

When Python enters the try block, it runs the code normally. If no exception occurs, Python skips the except block. If an exception occurs, Python stops the rest of the try block and looks for an except block that matches the exception type.

Recover from invalid integer input
text = "abc"

try:
    number = int(text)
    print(number)
except ValueError:
    print("That text cannot be converted to an integer.")

Without the try statement, int("abc") would stop the program with a ValueError. With the try statement, the program can display a friendly message and continue.

The lesson shows a reciprocal example that loops through values until it finds one that works. It also introduces sys.exc_info(), which can show information about the current exception. This can be useful while learning, but most user-facing programs should print clear, specific messages rather than raw exception internals.

Exception information while experimenting
import sys

random_list = ["a", 0, 2]

for value in random_list:
    try:
        print("The value is", value)
        reciprocal = 1 / int(value)
        break
    except Exception:
        print("Error!", sys.exc_info()[0], "occurred.")
        print("Next value.")
        print()

print("The reciprocal of", value, "is", reciprocal)

The example intentionally catches broad exceptions while exploring values. In larger programs, avoid a bare except: because it catches almost everything and can hide bugs. Prefer specific exception types, or at least use except Exception as error: so the error object is available. Most everyday runtime exceptions inherit from Exception, while special exceptions such as KeyboardInterrupt and SystemExit are normally left alone.

Access the exception object
try:
    result = 1 / 0
except Exception as error:
    print("Error!", error.__class__, "occurred.")
    print(error)

4. Catching Specific Exceptions

Source pages 9-10

A single try block can have multiple except clauses. This lets your program respond differently to different problems. Only one matching except block runs for a single exception. Python checks the clauses in order from top to bottom.

Multiple except clauses
try:
    index = int(input("Enter an index: "))
    names = ["Ada", "Grace", "Guido"]
    print(names[index])
except ValueError:
    print("Please enter a whole number.")
except IndexError:
    print("That index is not in the list.")

The first exception handles a conversion problem. The second handles a list-index problem. This is better than treating every problem the same way because the user gets a message that matches what actually went wrong.

The source lesson uses a function that can produce different exceptions depending on the input. With fun(3), the calculation tries to divide by zero. With a value greater than or equal to 4, the variable b may not be assigned before it is printed, creating a name or local-variable problem depending on exact code structure.

Multiple error paths
def fun(a):
    if a < 4:
        b = a / (a - 3)

    print("Value of b =", b)

try:
    fun(3)
except ZeroDivisionError:
    print("ZeroDivisionError occurred and was handled.")
except NameError:
    print("NameError occurred and was handled.")
except UnboundLocalError:
    print("A local variable was referenced before assignment.")

Order matters

Put more specific exception handlers before broader ones. If except Exception: appears first, it will catch many errors before the more specific handlers get a chance.

5. try with else and finally

Source page 11

A full exception-handling structure can include try, except, else, and finally. The else block runs only when the try block completes without an exception. The finally block runs whether an exception happened or not.

Exception block flow

Block Purpose When it runs
tryContains code that might raise an exception.Always starts first.
exceptHandles a matching exception.Only if that exception occurs.
elseContains success-only code.Only if the try block has no exception.
finallyContains cleanup code.Always runs after try/except/else.

finally is often used for cleanup: closing resources, releasing locks, or printing a final status message. In file work, the with statement handles file cleanup for you, but finally is still an important general pattern.

else and finally example
def aby_b(a, b):
    try:
        c = (a + b) / (a - b)
    except ZeroDivisionError:
        print("The calculation divided by zero.")
    else:
        print(c)
    finally:
        print("This is always executed.")

aby_b(5.0, 5.0)
aby_b(2.0, 3.0)

In the first call, a - b is zero, so the except block runs and else does not. In the second call, the calculation succeeds, so else prints the result. In both calls, finally prints its message.

6. Raising Exceptions

Source page 12

Sometimes Python raises an exception automatically. Other times, your code should raise one on purpose. Raising an exception means your program has detected a condition that should not be accepted. Use the raise keyword followed by an exception object.

Raise a general exception
y = -1

if y < 0:
    raise Exception("Sorry, numbers below zero are not allowed.")

A general Exception works, but a specific exception type usually communicates the problem better. If the problem is the type of the value, raise TypeError. If the type is correct but the value is unacceptable, raise ValueError.

Raise a TypeError
y = "hello"

if not isinstance(y, int):
    raise TypeError("Only integers are allowed.")

The isinstance() function checks whether an object belongs to a particular type or class. This is useful in validation code because you can reject the wrong type before trying operations that would fail later.

Raise early, explain clearly

Good exception messages describe what was wrong and what kind of value was expected. That message helps both the programmer and the person using the program.

7. User-Defined Exceptions

Source page 13

Python also lets you create your own exception classes. A custom exception is useful when your program has a domain-specific problem that deserves a clear name. In the lesson example, the program asks for a number between 10 and 50. Values below the range and above the range are different conditions, so the code defines separate exception classes for each.

A custom exception class should inherit directly or indirectly from Exception. The class can be empty at first. The name itself communicates the error category, and the docstring explains when the exception is used.

Custom range exceptions
class Error(Exception):
    """Base class for other exceptions."""
    pass


class ValueTooSmallError(Error):
    """Raised when the input value is too small."""
    pass


class ValueTooLargeError(Error):
    """Raised when the input value is too large."""
    pass


while True:
    try:
        number = int(input("Enter any value in the 10 to 50 range: "))

        if number < 10:
            raise ValueTooSmallError
        elif number > 50:
            raise ValueTooLargeError

        break
    except ValueTooSmallError:
        print("Value is below range. Try again.")
    except ValueTooLargeError:
        print("Value is out of range. Try again.")

print("Great! Value is in the correct range.")

This example combines several ideas from earlier chapters: a while True loop, input, conversion with int(), conditions, raise, custom exception classes, and break. The loop continues until the entered value passes validation.

1. Secure Communication

Source pages 4-5 and 7

Cryptography is the science of secure communication in the presence of third parties. The phrase "third parties" matters: the problem is not simply sending a message from one person to another, but sending it while someone else may be able to observe, copy, delay, alter, or impersonate part of the communication.

Cryptography appears anywhere information needs protection. Online banking and e-commerce use it to protect account details, payment data, and session traffic. Digital signatures use cryptographic techniques to verify the source and integrity of documents. Password systems should not store plaintext passwords; they should store password hashes produced by appropriate password-hashing algorithms. Military and intelligence systems use cryptography to protect classified communication.

The established needs for secure communication are secrecy, authentication, and message integrity. Secrecy means only the intended receiver should understand the message. Authentication means the parties involved can confirm identity: the sender is who they claim to be, and the receiver is the intended receiver. Message integrity means the communication has not been changed maliciously or accidentally during transmission.

Security goals

Goal Meaning Beginner example
Secrecy Only the intended receiver can understand the message. An encrypted banking session keeps account data unreadable to observers.
Authentication Parties can confirm identity or source. A login system checks that a user knows the correct credentials.
Integrity Data has not been altered. A message digest changes when a document is modified.

Use this knowledge responsibly

Cryptography is a defensive security topic. The examples in this chapter are for learning, protecting your own data, and understanding secure systems. Do not use these techniques to access, alter, or hide activity on systems you do not own or have permission to test.

2. Core Cryptography Terminology

Source pages 6-8

Cryptography uses a vocabulary that can feel abstract until you connect each word to the life of a message. The original readable message is called plaintext or cleartext. After an encryption algorithm transforms it, the unreadable result is ciphertext. Encryption converts plaintext into ciphertext. Decryption converts ciphertext back into plaintext.

Many algorithms also use a key. A key is a string of numbers, bytes, or characters used as an input to the algorithm. If the same secret key is used for both encryption and decryption, the algorithm is symmetric. If one key encrypts and a different related key decrypts, the algorithm is asymmetric.

Term reference

Term Meaning
PlaintextThe original readable message, often denoted as P.
CiphertextThe encrypted message, often denoted as C.
EncryptionThe process of encoding plaintext into ciphertext, often denoted as E.
DecryptionThe process of decoding ciphertext back into plaintext, often denoted as D.
CipherA method or algorithm for encrypting messages.
KeyA secret or public input used by the algorithm to transform data.

A common way to describe the relationship is C = E(P), meaning encryption turns plaintext into ciphertext. Decryption reverses that relationship: D(C) = P. In real algorithms, the key is part of both operations, but the shorthand helps you see the direction of the transformation.

3. Symmetric Encryption

Source pages 9-10 and 28-29

Symmetric encryption uses the same key to encrypt and decrypt. That makes it efficient, but it creates a key-sharing problem: both parties need the same secret key, and the key must not be exposed. If an attacker gets the secret key, they can read the ciphertext and may be able to create convincing encrypted messages.

Symmetric algorithms include stream ciphers, block ciphers, substitution techniques, transposition techniques, and related hiding techniques such as steganography. These categories describe different ways of transforming or arranging data.

Symmetric algorithm families

Category Examples What it does
Stream cipherRC4, ChaCha20Encrypts plaintext one bit or byte at a time, useful for continuous streams.
Block cipherAES, DES, BlowfishEncrypts fixed-size blocks of plaintext under the same key.
SubstitutionCaesar, monoalphabetic, Playfair, Hill, polyalphabetic, one-time padReplaces symbols or groups of symbols according to a rule or key.
TranspositionRail fence, columnar transpositionRearranges the position of plaintext characters.
SteganographyEmbedding in images or audioHides the existence of a message inside another medium.

Key strength is a major part of symmetric encryption. Key length is measured in bits. A set of all possible keys for a cipher is called the key space. A 40-bit key has 2 ** 40 possible keys; a 128-bit key has 2 ** 128 possible keys. Each additional bit doubles the number of possible keys, which is why key length matters so much against brute-force guessing.

Brute force

A brute-force attack tries possible keys until one works. Good modern systems choose algorithms and key sizes that make brute force impractical with available computing power.

Symmetric encryption is fast, but it has a central limitation: the secret key must somehow reach the receiver. Any exposure of that key compromises the secrecy of the ciphertext. This is why modern secure systems often combine asymmetric methods for key exchange with symmetric methods for bulk data encryption.

4. Classical Ciphers: Caesar, Monoalphabetic, and Polyalphabetic

Source pages 11-19

Classical ciphers are useful teaching tools because their transformations are visible. They are not appropriate for protecting real secrets today, but they help you understand keys, substitution, frequency analysis, and reversible transformations.

A Caesar cipher shifts each letter by a fixed number of positions. With a shift of three, A maps to D, B maps to E, and so on, wrapping around at the end of the alphabet. The mathematical idea uses modular arithmetic. If letters are numbered from A = 0 through Z = 25, encryption can be described as (message_value + key) % 26. Decryption reverses the shift with (cipher_value - key + 26) % 26.

Caesar shift idea
alphabet = "ABCDEFGHIJKLMNOPQRSTUVWXYZ"
shifted = "DEFGHIJKLMNOPQRSTUVWXYZABC"

for plain, cipher in zip(alphabet, shifted):
    print(plain, "maps to", cipher)

The source chapter also shows a key-generation pattern for a polyalphabetic Caesar-style cipher. A keyword is repeated until it is the same length as the message. Then each message character is combined with the matching key character using ord(), chr(), and modulo arithmetic. The ord() function returns the Unicode code point for a single character; chr() converts an integer code point back into a character.

Repeat a keyword to message length
def generate_key(message, keyword):
    key = list(keyword)

    if len(message) == len(key):
        return "".join(key)

    for i in range(len(message) - len(key)):
        key.append(key[i % len(key)])

    return "".join(key)

print(generate_key("HELLOWORLD", "KEY"))

A monoalphabetic cipher substitutes each plaintext letter with one fixed ciphertext letter. Each letter must have a unique substitute so the mapping can be reversed. There are many possible mappings, but simple monoalphabetic substitution is still vulnerable to statistical analysis because common letters and word patterns leak clues.

Monoalphabetic dictionary pattern
monoalpha_cipher = {
    "a": "m", "b": "n", "c": "b", "d": "v", "e": "c",
    "f": "x", "g": "z", "h": "a", "i": "s", "j": "d",
    "k": "f", "l": "g", "m": "h", "n": "j", "o": "k",
    "p": "l", "q": "p", "r": "o", "s": "i", "t": "u",
    "u": "y", "v": "t", "w": "r", "x": "e", "y": "w",
    "z": "q", " ": " "
}

message = "good morning"
encrypted = []

for letter in message:
    encrypted.append(monoalpha_cipher.get(letter, letter))

print("".join(encrypted))

To decrypt a monoalphabetic cipher, create the inverse dictionary by switching keys and values. The original dictionary maps plaintext to ciphertext. The inverse dictionary maps ciphertext back to plaintext.

A polyalphabetic cipher uses multiple substitution alphabets in sequence. Instead of applying the same shift to every letter, it changes the shift according to a key pattern. This reduces some obvious frequency patterns, which is why polyalphabetic ciphers were historically harder to break than a simple Caesar cipher.

The chapter also describes using a keyword to shift the alphabet. For example, a key such as KIND can be placed at the start of the cipher alphabet, duplicate letters removed, and the rest of the alphabet appended afterward. The important rule is one-to-one mapping: no plaintext letter should map to two ciphertext letters, and no ciphertext letter should map back to two plaintext letters.

5. Modern Symmetric Algorithms and Python Libraries

Source pages 20-28

Modern encryption should use established, reviewed libraries instead of handmade ciphers. Classical examples teach mechanics, but real confidentiality depends on mature algorithms, correct modes, safe key generation, authentication, and careful storage of secrets.

DES, the Data Encryption Standard, was designed as a block cipher that encodes plaintext in 64-bit chunks. Its effective 56-bit key is too small for modern use. The chapter includes DES3 examples through PyCryptodome, but for new real-world systems, choose modern authenticated encryption such as Fernet for beginner Python work or well-reviewed AES modes through a trusted library.

AES, the Advanced Encryption Standard, is a block cipher established by NIST in 2001. It encrypts data in 128-bit blocks and supports 128, 192, and 256-bit keys. The source lesson uses PyCryptodome's Crypto.Cipher.AES with EAX mode, which produces both ciphertext and an authentication tag. The tag matters because decryption alone does not prove the message was not modified.

AES EAX shape
from Crypto.Cipher import AES

key = b"Sixteen byte key"
data = b"Secret message"

cipher = AES.new(key, AES.MODE_EAX)
nonce = cipher.nonce
ciphertext, tag = cipher.encrypt_and_digest(data)

decipher = AES.new(key, AES.MODE_EAX, nonce=nonce)
plaintext = decipher.decrypt(ciphertext)

try:
    decipher.verify(tag)
    print("The message is authentic:", plaintext)
except ValueError:
    print("Key incorrect or message corrupted")

The cryptography package's Fernet feature gives beginners a safer high-level symmetric encryption interface. Fernet generates keys, encrypts bytes, authenticates messages, and decrypts with the same key. The message must be converted to bytes before encryption, usually with encode(). After decryption, convert bytes back to a string with decode().

Fernet symmetric encryption
from cryptography.fernet import Fernet

message = "Hey, Can I have some rice"

key = Fernet.generate_key()

encrypted_message = fernet.encrypt(message.encode())
print("encrypted string:", encrypted_message)

print("decrypted string:", decrypted_message)

Shannon's characteristics of good ciphers

  • The amount of secrecy needed should determine the amount of labor appropriate for encryption and decryption.
  • The key set and enciphering algorithm should be free from unnecessary complexity.
  • The implementation should be as simple as possible.
  • Errors in ciphering should not propagate and corrupt more of the message.
  • The ciphertext should be no larger than the original message when possible.

6. Asymmetric Encryption

Source pages 30-35

Asymmetric encryption uses a pair of keys. A public key can be shared and used for encryption. A private key must be kept secret and used for decryption. A message encrypted with the public key can only be decrypted with the related private key. This removes the need to secretly transmit the decryption key to every sender.

RSA and ElGamal are two well-known public-key algorithms. RSA was developed by Ron Rivest, Adi Shamir, and Len Adleman. It has historically used variable key sizes such as 512, 1024, and 2048 bits, though small sizes are not appropriate for modern security. ElGamal also uses variable key sizes and appears in protocols such as PGP.

RSA educational example shape
import rsa

public_key, private_key = rsa.newkeys(512)

message = "Welcome to Ontario"
encrypted_message = rsa.encrypt(message.encode(), public_key)

decrypted_message = rsa.decrypt(encrypted_message, private_key).decode()

print("original string:", message)
print("encrypted string:", encrypted_message)
print("decrypted string:", decrypted_message)

Asymmetric encryption is powerful, but it is not a replacement for symmetric encryption in every situation. It is slower. Larger asymmetric keys may provide security comparable to much smaller symmetric keys. It can also be vulnerable to man-in-the-middle attacks if public keys are not authenticated. This is why certificates and public key infrastructure matter.

Symmetric versus asymmetric

KeysSame secret key encrypts and decrypts.Public key and private key pair.

7. Authentication, Message Digests, and Digital Signatures

Source pages 36-41

Authentication validates identity or the integrity of data. The chapter groups authentication technologies into message digests or message authentication codes, digital signatures, and public key infrastructure. These tools answer different questions: Did the data change? Did this sender create or approve it? Does this public key belong to the party it claims to represent?

A message digest is a fingerprint for data. The process of creating a digest is called hashing. A hash function is one way: it should be infeasible to reverse the digest into the original message, and infeasible to deliberately construct two different messages with the same digest. Hashes are commonly used to detect changes, compare files, and support password storage workflows.

Message digest with hashlib
import hashlib

update_bytes = b"Python123"

my_hash1 = hashlib.md5()
my_hash1.update(update_bytes)
print("MD5:", my_hash1.hexdigest())
print("Digest size:", my_hash1.digest_size)

my_hash2 = hashlib.sha256()
my_hash2.update(update_bytes)
print("SHA256:", my_hash2.hexdigest())
print("Digest size:", my_hash2.digest_size)

MD5 appears in the source material as a common historical hash algorithm, but it should not be used for modern security decisions. SHA-256 is stronger for general integrity checks. Password storage should use password-hashing algorithms such as bcrypt, not plain MD5 or plain SHA-256.

A digital signature is a cryptographic protocol that acts like a digital mark only the sender can make. It gives the receiver a way to check source and integrity. A valid signature should be authentic and hard for someone else to forge. In practice, a message digest is created, signed with a private key, and verified with the sender's public key.

Digital signature shape with PyNaCl
from nacl.signing import SigningKey, VerifyKey

signing_key = SigningKey.generate()
signed = signing_key.sign(b"This key is Generated String key")

verify_key = signing_key.verify_key
verify_key_bytes = verify_key.encode()

verify_key = VerifyKey(verify_key_bytes)
verify_key.verify(signed)
verify_key.verify(signed.message, signed.signature)

A useful verification exercise modifies a signed message to demonstrate failure. If a signed message is altered, verification should fail and the library should raise a signature error. That is the point: signatures do not merely attach a name to a message; they help detect tampering.

8. Passwords, Hashes, and Authentication Systems

Source pages 39 and 42

A password is a secret character string known to the user and the authentication system. A responsible system should not store the plaintext password. Instead, it stores a password hash produced by a password hashing library. When the user logs in, the entered password is hashed and checked against the stored value.

The source lesson asks for a simple authentication system using bcrypt and a dictionary as a database. That is appropriate for practice, but real systems need a real database, rate limiting, secure sessions, account recovery controls, and careful operational security.

Password risks

  • An attacker may learn a password through social engineering.
  • An attacker may crack a weak password through brute force or guesswork.
  • A password may be exposed if sent over an unprotected network.
  • An encrypted or captured password-like value may be replayed if the protocol allows it.
bcrypt workflow shape
import bcrypt

password = "correct horse battery staple"

hashed_password = bcrypt.hashpw(password.encode(), bcrypt.gensalt())

is_valid = bcrypt.checkpw(password.encode(), hashed_password)
print(is_valid)

The key habit is that you verify passwords with the hashing library instead of manually comparing raw password text. If the entered password is correct, the check function returns true. If it is wrong, it returns false.

9. Kerberos, Personal Tokens, Biometrics, and Digital Certificates

Source pages 43-47

Cryptography supports several authentication technologies beyond passwords. Kerberos is an authentication service that uses symmetric key encryption and a key distribution center. A Kerberos authentication server stores symmetric keys and information about which users have access to which network services.

Personal tokens are hardware devices that generate or store authentication values. A storage token holds a secret value and unlocks it with a PIN. A synchronous one-time-password token generates a new value periodically based on time and a secret. A challenge-response token computes an answer based on a server's challenge. A digital-signature token holds a private key and signs supplied data. Tokens may appear as smart cards, USB tokens, handheld devices, or other physical forms.

Biometrics use biological characteristics for authentication. Examples include fingerprints, voice, handwriting, face recognition, retinal scans, and hand geometry. Biometrics can help identify a person, but they do not by themselves secure information while it travels over a network.

A digital certificate is a signed statement by a trusted party that another party's public key belongs to them. A certificate includes identity information, a public key, and a signature from a certificate authority. Top-level certificate authorities use self-signed root certificates. Name recognition and trust matter because anyone can technically start a certificate authority, but not every authority is trusted by browsers or operating systems.

10. Cryptanalysis and Base64

Source pages 48-50

Cryptanalysis is the process of breaking or analyzing an encryption code. It can involve trying to recognize patterns in encrypted messages, infer meaning without decrypting the message, deduce a key, exploit weaknesses in an implementation or environment, or find general weaknesses in an algorithm. Understanding cryptanalysis helps explain why modern systems avoid homemade encryption.

Base64 appears at the end of Lesson 7. It is often confused with encryption, but it is not encryption and does not provide confidentiality. Base64 encodes binary data into printable ASCII characters so it can pass through text-based systems such as JSON, XML, email, or older protocols that may not handle raw bytes safely.

Base64 works by converting data to bytes, encoding those bytes into Base64 bytes, then decoding the result into a printable string. Decoding reverses the process. Anyone can decode Base64 if they have the encoded text, so it should never be used as a secrecy mechanism.

Base64 encode and decode
import base64

message = "Hello, World!"

byte_conversion = message.encode("utf-8")
encoded_bytes = base64.b64encode(byte_conversion)
encoded_message = encoded_bytes.decode("utf-8")

print("Encoded message:")
print(encoded_message)

decoded_conversion = encoded_message.encode("utf-8")
decoded_bytes = base64.b64decode(decoded_conversion)
decoded_message = decoded_bytes.decode("utf-8")

print("Decoded message:")
print(decoded_message)

Base64 is not security

If a value is Base64 encoded, it is only represented differently. It is not protected. Use encryption when secrecy is required and hashing/signatures when integrity or authentication is required.

1. Network Traffic and Packets

Source page 3

Network traffic is the movement of data across a network. When a computer opens a website, checks email, resolves a domain name, streams media, or talks to another device, the data is broken into packets. A packet is a small unit of network communication with structured information such as where it came from, where it is going, what protocol it uses, and what data it is carrying.

Traffic volume can be described with the relationship Traffic volume = Traffic intensity * Time. Traffic intensity is how much data is moving in a period, and time is how long the traffic is observed. In practice, this helps explain why a busy network capture fills up quickly: even normal background communication can create many packets every second.

Packet analysis usually begins by looking at a few repeated fields. Time tells you when the packet was seen. Source tells you which host sent it. Destination tells you which host should receive it. Protocol tells you the communication rules being used. Info gives a short human-readable summary of what the packet appears to be doing.

Common protocols in a capture

Protocol What a beginner should recognize
TCPA connection-oriented transport protocol used by many reliable network services.
UDPA connectionless transport protocol often used when speed or simplicity matters.
DNSTranslates domain names such as example.com into IP addresses.
ARPMaps IP addresses to hardware addresses on a local network.
SMTPA mail-related protocol used for sending email between systems.

Authorization comes first

Packet capture can expose private information. Capture only your own lab traffic, classroom lab traffic, or traffic you have been authorized to inspect. If you are unsure whether you have permission, do not capture.

2. Wireshark: Capturing, Filtering, and Saving Traffic

Source pages 4-7

Wireshark is a free and open-source packet analyzer. It is widely used for troubleshooting, learning protocols, protocol development, security analysis, and network education. Wireshark can capture live traffic from a network interface, and it can also open previously saved capture files. Those saved files are often stored in .pcap format, which is a common packet capture file format used by many tools.

A live capture depends on the network interface you select. A computer may have Ethernet, wireless 802.11, loopback, VPN, or other interfaces. On Linux and macOS, ifconfig may show interface names and addresses. On Windows, ipconfig is the usual command. In Wireshark, you choose the interface that represents the traffic you want to observe, then begin the capture. The packet list may fill quickly, which is normal.

To find packets related to an IP address, use a filter such as ip.addr == 192.168.1.10. To focus on a protocol, type the protocol name, such as tcp, udp, dns, arp, or smtp.

3. Reading PCAP Files with dpkt

Source pages 7-8

A packet capture becomes more useful when Python can read it. The dpkt module is a fast, simple packet creation and parsing library. It includes definitions for many basic TCP/IP protocols. In Lesson 8, dpkt is used to open a saved .pcap file and print source and destination IP addresses.

Install it with pip install dpkt. The basic reading pattern is: open the capture file in binary mode, pass the file object to dpkt.pcap.Reader, loop through each packet, parse the Ethernet frame, retrieve the IP layer, and convert the packed network-address bytes into readable dotted IPv4 strings.

Read source and destination IP addresses from a PCAP
import dpkt
import socket

def print_packets(pcap):
    for timestamp, buffer in pcap:
        ethernet = dpkt.ethernet.Ethernet(buffer)
        ip = ethernet.data

        source_ip = socket.inet_ntoa(ip.src)
        destination_ip = socket.inet_ntoa(ip.dst)

        print("Source:", source_ip, "Destination:", destination_ip)

with open("capture.pcap", "rb") as file:
    pcap = dpkt.pcap.Reader(file)
    print_packets(pcap)

The loop variable timestamp represents when the packet was captured. The variable buffer contains the raw packet bytes from the file. The expression dpkt.ethernet.Ethernet(buffer) interprets those bytes as an Ethernet frame. If that frame contains IP traffic, ethernet.data gives access to the IP packet.

IP addresses in packet structures are stored as packed bytes, not as familiar strings like 192.168.1.10. The function socket.inet_ntoa() converts packed IPv4 bytes into dotted-quad text. The reverse operation, socket.inet_aton(), converts a dotted IPv4 string into packed bytes.

Beginner debugging note

Not every captured frame is guaranteed to be the exact protocol shape your code expects. Real parsers often check whether a frame contains IP before reading ip.src or ip.dst. For a classroom exercise, a small capture containing known IP traffic is easier to reason about.

4. What Scapy Does and Why It Matters

Source pages 9-12

Scapy is a Python program and library for packet manipulation. It can create packets, decode packets, send packets, receive replies, sniff traffic, and work with packet capture files. Scapy is best understood as a powerful interactive packet manipulation program because it lets you describe packets directly in Python instead of writing large amounts of low-level networking code.

Scapy can be used for scanning, tracerouting, probing, network discovery, unit tests, and protocol experiments. It can replace or overlap with parts of tools such as hping, arping, tcpdump, tshark, and some Nmap-style probing. That does not mean it should be used carelessly. A tool that can generate packets can also generate unwanted traffic, so use Scapy inside labs and permissioned environments.

One reason Scapy is approachable is that it treats packets as stacked layers. You can create an IP layer, place a TCP layer on top of it, and attach raw data as a payload. Each layer has fields with defaults, so you only need to set the fields that matter for the experiment. This is much friendlier than manually creating every byte of every header.

Why Scapy is useful

Feature Beginner meaning
Packet forgingYou can construct packets with specific layers and field values.
DissectionYou can decode packet bytes into readable protocol fields.
Send and receiveYou can send a probe and inspect the response in Python.
Raw data preservationYou can keep the packet data and reinterpret it later from a different viewpoint.
Layer stackingYou build packets by combining protocol layers with the / operator.

Lesson 8 makes an important point about interpretation. Some tools probe the network and immediately reduce the result to one conclusion. Scapy keeps the raw stimulus-response data, which means the same results can be examined in more than one way. For example, a set of TCP probe replies might later be grouped by TTL behavior without sending the probes again.

6. Packets as Stacked Layers

Source pages 15-17

In Scapy, a packet is built by stacking layers with the / operator. A single layer such as IP() creates an IP packet with default field values. Adding /TCP() places a TCP layer inside the IP packet. Adding a string places raw payload data after the protocol headers.

Basic layer stacking
from scapy.all import *

packet1 = IP()
packet2 = IP() / TCP()
packet3 = Ether() / IP() / TCP()
packet4 = IP() / TCP() / "GET / HTTP/1.0\r\n\r\n"
packet5 = Ether() / IP() / IP() / UDP()
packet6 = IP(proto=55) / TCP()

packet2.show()

The / operator is not division in this context. Scapy overloads it to mean "put this layer inside or after the previous layer." Some lower-layer defaults can be influenced by upper layers. For example, when you stack TCP inside IP, Scapy understands that the IP protocol field should describe TCP.

You can set fields while constructing a layer. The expression IP(dst="8.8.8.8") creates an IP packet whose destination is 8.8.8.8. Scapy also accepts hostnames and CIDR notation in many places. For example, IP(dst="scanme.nmap.org") uses a hostname, and IP(dst="8.8.8.8/30") represents a small range of addresses.

Destination fields and packet expansion
from scapy.all import *

packet = IP(dst="8.8.8.8")
print(packet.dst)

range_packet = IP(dst="8.8.8.8/30")
print([item.dst for item in range_packet])

ttl_packet = IP(ttl=[1, 3, 5, (7, 10)]) / TCP()
print([item.ttl for item in ttl_packet])

Fields can be read and changed with attribute syntax. If a = IP(dst="192.168.1.1"), then a.ttl reads the time-to-live value. Assigning a.ttl = 32 changes that field. The show() method prints a detailed view of the packet fields before Scapy fully assembles the packet. The show2() method assembles the packet first, which causes calculated fields such as checksums and header lengths to be filled.

Build, convert, and dissect
from scapy.all import *

a = Ether() / IP(dst="www.slashdot.org") / TCP() / "GET /index.html HTTP/1.0\n\n"

hexdump(a)

raw_bytes = raw(a)
c = Ether(raw_bytes)
c.show()
c.hide_defaults()
c.show()

The function raw() converts the Scapy object into packet bytes. Passing those bytes back to Ether() asks Scapy to dissect them into layers again. The method hide_defaults() removes fields that are equal to their default values, which can make the object easier to read.

7. Generating Sets of Packets

Source page 18

Scapy can treat some field values as sets. If a field is given a list, tuple range, or address range, Scapy can generate multiple packets from one expression. This is useful when you want to create a small controlled group of probes or examples without writing repetitive loops by hand.

Packet sets from field values
from scapy.all import *

a = IP(dst="www.slashdot.org/30")
print([packet.dst for packet in a])

b = IP(ttl=[1, 2, (5, 9)])
print([packet.ttl for packet in b])

c = TCP(dport=[80, 443])
print([(packet.dst, packet.dport) for packet in a / c])

When you combine two packet expressions that each expand to multiple values, Scapy can create a Cartesian product. In plain English, it tries every relevant combination. If one destination expression creates four destination values and one TCP expression creates two destination ports, combining them can create eight packets.

Some operations do not work directly on packet sets. If a packet set is not explicitly unrolled into individual packets, an operation may use only the first element. When you want a list-like object containing all generated packets, use a list comprehension or PacketList.

PacketList pattern
from scapy.all import *

a = IP(dst="www.slashdot.org/30")
c = TCP(dport=[80, 443])

packets = PacketList([packet for packet in a / c])
packets.summary()

9. Sending and Receiving Packets

Source pages 21-23 and 28

Scapy has separate functions for sending only, sending at a specific layer, and sending while collecting responses. This distinction matters. A send-only function is like putting a packet onto the wire and not listening for an answer. A send-and-receive function is like sending a question and then recording who answered.

send() sends Layer 3 packets. That usually means you provide an IP packet and Scapy handles the needed Layer 2 details. It does not receive packets. The options count, loop, and inter control repetition. count sends an exact number of packets. loop repeats until interrupted when nonzero. inter waits a number of seconds between sends.

send() examples for a permissioned lab
from scapy.all import *

lab_target = "192.168.56.102"

send(IP(dst=lab_target) / TCP(dport=53, flags="S"))
send(IP(dst=lab_target) / TCP(dport=53, flags="S"), count=10)
send(IP(dst=["192.168.56.102", "192.168.56.103"]) / TCP(dport=53, flags="S"))

sendp() sends at Layer 2. In this case, you must provide the Layer 2 header, such as an Ethernet layer. You can choose the interface with iface. If you do not choose an interface, Scapy uses its configured default, conf.iface.

sendp() examples
from scapy.all import *

sendp(Ether() / IP(dst="192.168.56.102", ttl=(1, 4)), iface="eth1")
sendp("I'm travelling on Ethernet", iface="eth1", loop=1, inter=0.2)
sendp(rdpcap("lab_capture.pcap"))

Send-and-receive functions collect responses. sr() sends packets and receives answers. It returns two packet lists: answered stimulus-response pairs and unanswered probes. sr1() returns only the first response. srloop() repeats the send-and-receive process in a loop and displays responses as they arrive.

Send and receive patterns
from scapy.all import *

ans, unans = sr(IP(dst="192.168.56.102") / TCP(dport=[21, 22, 23]), timeout=2)
ans.summary()

first_reply = sr1(IP(dst="192.168.56.102") / ICMP() / "XXXXXXXXXXX", timeout=2)
print(first_reply.summary() if first_reply else "No reply")

packet = IP(dst="192.168.56.102") / ICMP()
srloop(packet, count=3)

Do not loop against public targets

Scapy supports looped sending, but it needs restraint. For learning, use a private lab address, virtual machine, or instructor-provided target. Avoid repeated traffic against public systems.

10. Fuzzing, Importing, Exporting, and Sniffing

Source pages 24-27

Scapy can do more than construct ordinary packets. It can fuzz fields, import and export packet data, and sniff live or offline traffic. These features are useful, but they also require judgment. Fuzzing and live sniffing should stay inside controlled labs.

Fuzzing means intentionally generating unusual or randomized values to see how a target or parser behaves. Scapy's fuzz() function changes default values that are not automatically calculated, such as many protocol fields. It avoids recalculating fields such as checksums in the wrong way. The source example uses UDP and NTP. It also notes that if you fuzz the IP layer, src and dst are not randomly generated unless you use helpers such as RandIP().

Fuzzing shape for an isolated lab target

1. What Web Scraping Is

Source page 3

Web scraping means extracting data from a website. A person could do this manually by opening a page, copying information, and pasting it into a spreadsheet, but automation is often faster and less repetitive. A script can request a page, inspect its HTML, select the pieces of information that matter, and save the result in a format that is easier to analyze.

A simple scraping workflow has four stages. First, the script retrieves the page. Second, it parses the page into a structure Python can navigate. Third, it extracts values from the relevant elements. Fourth, it stores the extracted values. In Lesson 9, a common example is the site http://books.toscrape.com/, where book titles are stored inside repeated product cards.

Basic scraping workflow

  1. Request the page HTML from the server.
  2. Parse the HTML into a searchable structure.
  3. Select the relevant elements by tag, class, ID, CSS selector, or XPath.
  4. Extract the text or attribute values you need.
  5. Clean and organize the values.
  6. Export the result to CSV, Excel, or another format.

Web scraping can be useful for research, price monitoring, classroom exercises, data collection from public pages, and transforming scattered web information into a structured dataset. It can also become fragile quickly, because web pages are designed primarily for humans and browsers, not always for scripts.

2. Legal and Ethical Boundaries

Source page 4

Web scraping is not automatically illegal, and it is not automatically acceptable either. The safest beginner rule is to scrape only pages you are allowed to use, keep requests small and respectful, and avoid collecting sensitive personal data. Publicly visible information is not the same thing as unrestricted information. A website may have terms of service, copyright rules, rate limits, or anti-automation expectations.

The chapter emphasizes that scraping is usually treated differently when the data is public, the website does not forbid the activity, and the purpose is ordinary research or analysis. It becomes risky and often illegal when the data is used for malicious purposes, sold improperly, or includes sensitive information such as personal addresses, phone numbers, private account details, or other protected data.

Not legal advice

This chapter teaches technical concepts, not legal advice. Before building a real scraper, read the site's terms of service, check whether an API is available, respect rate limits, and avoid collecting or sharing personal information.

Responsible scraping habits

  • Prefer an official API when one exists.
  • Read the website's terms and copyright policy.
  • Keep request volume low while learning.
  • Do not scrape login-protected or private data without permission.
  • Do not collect personal information for spam, resale, harassment, or profiling.
  • Identify and document the source of your dataset.

3. Why Web Scraping Can Be Difficult

Source page 5

The web is not one consistent database. It grew organically from many people, technologies, design systems, frameworks, and business goals. Two pages may look similar to a person but have completely different HTML underneath. A scraper that works perfectly on one page may fail on another page because the class names, element nesting, JavaScript behavior, or pagination pattern is different.

The first challenge is variety. Every website needs personal treatment. You may see repeated ideas, such as headings, links, tables, lists, and product cards, but the exact markup is unique. A beginner scraper should start by inspecting the page carefully and choosing selectors that are specific enough to find the right data but not so brittle that a tiny layout change breaks everything.

The second challenge is durability. Websites change. A class name can be renamed, a product card can gain another wrapper element, a page can move from static HTML to JavaScript rendering, or a site can redesign its layout entirely. When this happens, a scraper may produce empty results or raise a stack trace. Good scraping code includes checks, clear errors, and small tests so you know when the page structure changes.

Maintenance is normal

A scraper is not a one-time spell. Treat it like code that depends on someone else's changing website. If the site changes, the scraper may need updates.

Source pages 6 and 18

Python has several web scraping libraries because different pages require different tools. Requests is excellent when the page content is available in the HTML response. Beautiful Soup is beginner-friendly for parsing and searching HTML. lxml is very fast and works well with XPath. Selenium automates a real browser and can handle pages whose content appears only after JavaScript runs.

5. Requests: Getting Web Pages and Sending Form Data

Source page 7

Web scraping usually begins with an HTTP request. HTTP is the protocol browsers use to request web pages from servers. A GET request asks for a resource, such as a page. A POST request sends data to a server, often from a form. Python includes lower-level networking tools, but the requests library makes common HTTP work easier to read and debug.

Install Requests
pip install requests
HTTP GET with Requests
import requests

url = "https://williscollege.com/"
response = requests.get(url, timeout=10)

print(response.status_code)
print(response.text[:500])

The response object contains several useful pieces of information. response.status_code tells you whether the server reports success, redirect, client error, or server error. response.text gives decoded text, which is usually what you want for HTML. response.content gives raw bytes, which can be useful for binary files or when you need exact byte-level data.

HTTP POST with form data
import requests

form_data = {
    "key1": "value1",
    "key2": "value2",
}

response = requests.post("https://williscollege.com/", data=form_data, timeout=10)
print(response.status_code)
print(response.text[:500])

When learning scraping, always inspect the status code before assuming your request succeeded. A script that blindly parses an error page may produce confusing results. In real scraping code, you might call response.raise_for_status() so HTTP errors become Python exceptions.

6. Beautiful Soup: Parsing and Searching HTML

Source pages 8-10

Beautiful Soup is a parsing library. It does not download pages by itself. Instead, it takes HTML that you already retrieved with Requests, Selenium, a file, or another source, and turns it into a parse tree. A parse tree is a navigable representation of the HTML document. You can search it by tag name, class, ID, CSS selector, text, or relationships between elements.

Install Beautiful Soup
pip install beautifulsoup4
Get HTML and read the page title
import requests
from bs4 import BeautifulSoup

url = "http://books.toscrape.com/"
response = requests.get(url, timeout=10)

soup = BeautifulSoup(response.text, "html.parser")
print(soup.title)

The parser name "html.parser" refers to Python's built-in HTML parser. It is convenient because it does not require an extra parser install. Beautiful Soup can also use other parsers, including lxml, when they are available.

The chapter shows repeated book titles inside h3 elements. Beautiful Soup can find those elements with find_all(). Some older examples use findAll(); it still appears in many tutorials, but find_all() is the modern Python-style spelling.

Find repeated title elements
import requests
from bs4 import BeautifulSoup

url = "http://books.toscrape.com/"
response = requests.get(url, timeout=10)
soup = BeautifulSoup(response.text, "html.parser")

book_titles = soup.find_all("h3")

for title in book_titles:
    print(title.get_text(strip=True))

CSS selectors are another way to find elements. If you know CSS, soup.select() can be very readable. For example, on the book scraping practice site, each product card uses the class product_pod, so soup.select(".product_pod") returns those cards. You can then search inside each card for a link, title, price, or other detail.

Use CSS selectors
import requests
from bs4 import BeautifulSoup

url = "http://books.toscrape.com/"
response = requests.get(url, timeout=10)
soup = BeautifulSoup(response.text, "html.parser")

book_cards = soup.select(".product_pod")

for card in book_cards:
    title_link = card.select_one("h3 a")
    if title_link:
        print(title_link["title"])

Beautiful Soup can also find elements by ID and other attributes. A common pattern is soup.find("div", attrs={"id": "some-id"}), which means "find the first div whose id attribute has this value." IDs should be unique on a page, while classes often repeat.

7. lxml and XPath

Source pages 11-12

lxml is a fast parsing library for HTML and XML. It is often chosen when performance matters or when a project uses XPath expressions. XPath is a query language for selecting nodes inside XML or HTML documents. Where CSS selectors often describe visual styling relationships, XPath can describe document paths and functions such as selecting text nodes.

Install lxml
pip install lxml

lxml needs HTML text before it can build a tree. Requests can provide that text. The html.fromstring() function parses the HTML string into a tree object, and tree.xpath() returns the nodes or values that match the XPath expression.

Parse with lxml and use XPath
import requests
from lxml import html

url = "http://books.toscrape.com/"
response = requests.get(url, timeout=10)

tree = html.fromstring(response.text)
titles = tree.xpath("//article[@class='product_pod']/h3/a/@title")

for title in titles:
    print(title)

The expression //article[@class='product_pod']/h3/a/@title means: find article elements whose class is product_pod, then go to their h3 child, then their a child, then return the link's title attribute. XPath can also use text() to return text nodes.

lxml and imperfect HTML

lxml is fast and powerful, but poorly formed HTML can make parsing harder. Beautiful Soup is often more forgiving for messy beginner examples, while lxml is excellent when the structure is predictable.

8. Selenium and WebDrivers

Source pages 13-19

Requests, Beautiful Soup, and lxml work well when the useful data is already present in the HTML returned by the server. Some websites, however, rely on JavaScript to fill in fields, menus, tables, or product listings after the first page load. In that case, a simple Requests call may retrieve an almost empty page shell. Selenium solves this by automating a real browser.

Selenium is an open-source browser automation tool. It is widely used for testing web applications, but it can also be used for scraping when the page must render JavaScript first. The tradeoff is speed. A real browser is heavier than a simple HTTP request, so Selenium is slower and consumes more CPU and memory.

Selenium requirements

  • A supported browser such as Chrome, Edge, Firefox, or Safari.
  • A compatible browser driver, such as ChromeDriver or GeckoDriver.
  • The Selenium Python package.
Install Selenium
pip install selenium

The driver version should match the browser you are automating. For Chrome, that usually means ChromeDriver. For Firefox, it means GeckoDriver. The driver is an executable file saved somewhere on your machine, and Selenium uses it to control the browser.

Open a page with Chrome WebDriver

Selenium can also work with Beautiful Soup. One common pattern is to let Selenium open the page and run the JavaScript, then read driver.page_source and pass that rendered HTML to Beautiful Soup. This gives you browser rendering plus Beautiful Soup's comfortable parsing methods.

9. Exporting Data to CSV and Excel

Source pages 20-22

Once a scraper extracts data, the result should be stored in a useful format. Pandas is a common choice because it can turn a list or dictionary of values into a DataFrame, which is a two-dimensional table with rows and columns. From there, exporting to CSV or Excel is straightforward.

Install pandas and Excel support
pip install pandas
pip install openpyxl

CSV stands for comma-separated values. It is plain text and works well for many simple datasets. Excel files are richer spreadsheet files and require an Excel-writing engine such as openpyxl. In both cases, the file extension matters. If you save a CSV without .csv or an Excel file without .xlsx, other programs may not recognize it correctly.

Export scraped titles to CSV
import pandas as pd

results = [
    "A Light in the Attic",
    "Tipping the Velvet",
    "Soumission",
]

df = pd.DataFrame({"book Title": results})

What PowerShell Scripts Do

PowerShell is both a command shell and a scripting language. A command shell lets you run commands one at a time. A scripting language lets you save several commands in a file so the computer can repeat them consistently. A PowerShell script is usually saved with the .ps1 extension.

Scripts are useful when a task has multiple steps, must be repeated often, or needs to behave the same way every time. Common examples include collecting logs, creating reports, managing users, checking folders, and backing up files. The assignment for this lesson asks you to build a Backup.ps1 script, so the main idea is: turn a repeated manual file task into a controlled program. 

# A tiny script can start with simple statements.
Write-Host "Starting backup check..."

$sourcePath = "C:\Projects\Website"
$destinationPath = "C:\Backups\WebsiteBackup"

Write-Host "Source: $sourcePath"
Write-Host "Destination: $destinationPath"

PowerShell commands are often called cmdlets. Many cmdlets use a verb-noun naming pattern, such as Get-ChildItem, Test-Path, Copy-Item, and New-Item. That pattern makes scripts easier to read because the command names describe the action and the target.

Running Scripts Safely

PowerShell does not treat scripts as casual text files. Scripts can modify files, change settings, or automate administrative tasks, so PowerShell includes execution policies. Use Get-ExecutionPolicy to view the current policy. A policy such as Restricted blocks script execution, while RemoteSigned allows local scripts and requires downloaded scripts to be trusted. 

Get-ExecutionPolicy

# A common student setup for local scripts:
Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned

When running a script, include the path. If the script is in the current folder, use .\ so PowerShell knows exactly which file you mean. This prevents accidental execution of another command with a similar name. 

# Run Backup.ps1 from the folder that contains the file.
.\Backup.ps1

# Run it with parameter values.
.\Backup.ps1 -SourcePath "C:\Projects\Website" -DestinationPath "C:\Backups\WebsiteBackup"

Variables and Strings

A variable stores a value so it can be reused later. PowerShell variable names begin with $. In a backup script, variables are helpful because the source folder, destination folder, file list, and status messages may be needed in several places.

Single quotes and double quotes behave differently. Single quotes keep text literal. Double quotes allow variable interpolation, which means PowerShell replaces the variable name with its value. For a more complex expression inside a string, wrap the expression in $(). 

$name = "Jordan"
$count = 3

Write-Host 'Hello, $name'
Write-Host "Hello, $name"
Write-Host "Files copied: $($count + 2)"

Expected output:

Hello, $name
Hello, Jordan
Files copied: 5

Scope and Profiles

Scope controls where a variable, function, or alias can be seen and changed. A variable created inside a script usually belongs to script scope, so it exists while that script is running. A variable created in the current shell belongs to the current local scope. Global scope is the broadest scope in the session.

  • Local scope: the current working scope.
  • Script scope: values that belong to the script while the script runs.
  • Global scope: values available broadly in the current PowerShell session.

Profiles are scripts that run when PowerShell starts. They are a way to customize your shell with a greeting, aliases, prompt settings, or helper functions. The assignment asks you to inspect the profile paths and create a current-user/current-host profile with a personalized greeting. 

$PROFILE | Select-Object *

if (-not (Test-Path $PROFILE.CurrentUserCurrentHost)) {
    New-Item -ItemType File -Path $PROFILE.CurrentUserCurrentHost -Force
}

Add-Content -Path $PROFILE.CurrentUserCurrentHost -Value 'Write-Host "Welcome back to PowerShell!"'

After editing a profile, open a new PowerShell session to test it. If the greeting appears, your profile customization is working.

Parameters

Parameters let the person running a script supply values at runtime. Without parameters, a backup script would only work for the folder names hard-coded inside the file. With parameters, the same script can back up different folders.

A param block belongs near the top of the script. You can add types such as [string] and attributes such as [Parameter(Mandatory)] so the script asks for required input instead of running with missing values. 

param(
    [Parameter(Mandatory)]
    [string]$SourcePath,

    [Parameter(Mandatory)]
    [string]$DestinationPath,

    [switch]$WebApp
)

Write-Host "Preparing to back up $SourcePath"

The [switch] type is useful for yes-or-no options. In this lesson, -WebApp can mean "also check whether this folder contains web app files such as HTML, JavaScript, or CSS."

Flow Control and Validation

Flow control decides which branch of code runs. The most common structure is if, elseif, and else. Validation uses flow control to check input before the script does work. For the backup assignment, validation should confirm that the source exists and that the destination does not already exist. 

if (-not (Test-Path $SourcePath)) {
    throw "Source path does not exist: $SourcePath"
}
elseif (Test-Path $DestinationPath) {
    throw "Destination already exists: $DestinationPath"
}
else {
    Write-Host "Validation passed."
}

For web app content, use Get-ChildItem with -Recurse to inspect the folder tree. Then check file extensions. The business rule is not just "copy files"; it is "when the web app option is selected, identify whether the source contains web app content." 

if ($WebApp) {
    $webFiles = Get-ChildItem -Path $SourcePath -Recurse -File |
        Where-Object { $_.Extension -in ".html", ".js", ".css" }

    if ($webFiles.Count -gt 0) {
        Write-Host "Web app content found: $($webFiles.Count) files"
    }
    else {
        Write-Host "No web app content found."
    }
}

Error Handling

Some errors are nonterminating, which means PowerShell reports the problem but may continue running. Other errors are terminating, which means the script stops. For deliberate assignment rules, use throw when the script should stop, such as a missing source folder or a destination that would overwrite an existing backup.

A try, catch, and optional finally block gives the script a clear error-handling structure. The risky work goes in try. The response to failure goes in catch. Cleanup or final status messages can go in finally. 

try {
    Copy-Item -Path $SourcePath -Destination $DestinationPath -Recurse -ErrorAction Stop
    Write-Host "Backup completed."
}
catch {
    Write-Error "Backup failed: $($_.Exception.Message)"
}
finally {
    Write-Host "Backup script finished."
}
